# 260218 归档改造实施计划（文档先行）

## 元信息

- NormativeSource: `docs/memories/archive-markdown-schema.md`
- Version: `md`
- OutOfScope: 灰度切换、双写、分批迁移

## 本轮边界（严格）

本轮只做文档，不改业务代码：

1. 先冻结规则，后实施代码；
2. 每一步必须有可执行验证项；
3. 任何超出本轮边界的代码动作，统一推迟到下一轮。

## 分步计划

### 步骤1：规范源冻结（本轮执行）

动作：

1. 在 memories 中确认唯一规范文件与版本标识；
2. 固化路径 `source_id/message_id.md` 与切换期读写策略；
3. 固化 `source_id` 规则（小写、长度上限 128、超限报错）。

验证：

- 规范引用链一致（index/design/architecture 均指向同一规范源）；
- 无“v1 作为现行规范”表述残留。

### 步骤2：迁移门禁文档化（本轮执行）

动作：

1. 固化一次性切换门禁（功能/数据/完整性/运维/审批）；
2. 明确完整性核对口径仅 `(chat_id, message_id)`；
3. 明确删除旧单文件前必须先生成 `archives/260218-old-markdown-archives.zip`。

验证：

- 门禁清单可直接用于 Go/No-Go 评审；
- 迁移前后动作顺序明确、无歧义。

### 步骤3：执行计划细化（本轮执行）

动作：

1. 将代码实施拆成小步（路径切换 -> 兼容读取 -> 全量补齐 -> 删除旧文件）；
2. 每步绑定测试与验收条件；
3. 增加回退条件与停止条件。

验证：

- 实施步骤可单独执行且可单独验收；
- 每一步都包含测试命令或核对动作。

### 步骤4：进入代码阶段前置条件（下一轮）

动作：

1. 用户确认文档版计划通过；
2. 再开始第一段代码改造（仅一小步，不并行大改）。

验证：

- 用户明确批准“进入代码阶段”；
- 本计划文档无占位、无冲突、无未决硬约束。
