# 一次性切换阈值执行计划（来源分桶归档）

## 计划头（强制字段）

- NormativeSource: `docs/memories/archive-markdown-schema.md`
- Version: `md.v1`
- OutOfScope: 灰度发布、双写过渡、多版本并行写

## 目标

在不引入灰度/双写的前提下，按门禁完成一次性切换判定（Go / No-Go）。

## 步骤1：前置核对（规范一致性）

- 动作：确认本计划与 `NormativeSource` 版本一致。
- 验证：检查 `Version` 与 schema 文档中的版本标识一致。
- 通过标准：版本一致；若不一致，停止执行并先更新计划。

## 步骤2：门禁验证（逐项）

- 动作：按 schema v1 的 5 类门禁执行检查：功能、数据、完整性、运维、审批。
- 验证：每一项都必须有“通过/失败 + 证据”。
- 通过标准：5/5 全通过才允许 Go。

## 步骤3：结果判定（Go/No-Go）

- 动作：汇总门禁结果，给出唯一结论。
- 验证：若任一门禁失败，结论必须为 No-Go。
- 通过标准：结论与门禁结果完全一致，不允许主观覆盖。

## 步骤4：记录与追踪

- 动作：将结果同步到进度与发布前检查记录。
- 验证：记录中包含失败项、风险说明、处理建议。
- 通过标准：可追溯且可复盘。

## 失败处理

- 任一门禁失败：立即 No-Go；
- 不得在缺证据状态下执行一次性切换；
- 需补齐失败项后重跑步骤2。
